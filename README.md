# 实时蜘蛛侠战衣（活体战衣）· 技术提示词

> 对齐「实时人体隐身（活体玻璃）」那套提示词的写法，把「隐身」换成「换肤」。
> 可以直接拿这份去喂给任意 coding agent 复现，也可以当发布文案。

做一个浏览器端实时「穿上蜘蛛侠战衣」效果：把人变成一套程序化生成的战衣，捏合手势触发变身、双手拉开一扇「传送窗」只让窗内的人变身。

**技术栈**：原生 WebGL2 单 pass 片元着色器（GLSL ES 3.0）做全部渲染与合成；MediaPipe **tasks-vision** 三个 task —— HandLandmarker 识别手势（拇指+食指捏合作为变身开关，双手 L 形作为窗口）、ImageSegmenter 实时抠人体 mask、FaceLandmarker 定位面罩眼睛。摄像头、mask、逐行躯干轴各走一张纹理，全部在 GPU 里合成，零素材、零上传、**wasm 与模型全部本地化，断网也能跑**。

**实现思路**：

1. **战衣的辨识度不在布料，在三样东西**：大白眼面罩、胸口蛛徽、蛛网线。三个全部用 SDF 程序化画，因此可以任意缩放、不依赖贴图。眼睛用「超椭圆 + 内角收尖」的杏仁形，单眼半宽取眼间距的 0.52 倍（这个比例是像不像的关键，给小了会瞬间变成普通红头套）。
2. **每帧把 Selfie Segmentation 的 mask 做两套模糊**：大半径的当高度场、取梯度作表面法线；小半径的单独当 alpha 边界。**这两者必须解耦** —— 用同一份大模糊同时当 alpha，战衣会糊到轮廓外一圈，形成「贴纸描边」式的溢色晕。
3. **红蓝分区不能用 mask 包围盒的横坐标**。人一张开手臂，包围盒就被手拉宽、躯干只占中间一小块，于是腋下侧条和手套全部错位、整条手臂还会被判成「腰以下」变蓝。正确做法：CPU 侧对 mask 逐行取「最长连续人体段」，得到每行的躯干中心与半宽，打成一张 1×64 的纹理传进 shader；shader 用相对躯干的坐标 `torsoU ∈ [-1,1]` 做分区，`|torsoU|>1` 就是伸出去的手臂，强制走暖色。
4. **布料**：六边形网格 SDF，网格坐标用「人体框归一化坐标 + 法线梯度扰动」，于是网格会贴着身体起伏、随人远近缩放，而不是固定在屏幕上滑。
5. **蛛网**：以胸口为原点的极坐标，径向线的角度阈值取 `1/r`，保证线在远处也是恒定粗细（像缝线，不是扇形）；同心弧在两条径向线之间做下垂。蛛网只印在暖色区 —— 经典战衣的蓝色部分是纯色布，这一条让整体立刻「对味」。暗线外侧补一圈亮边，做出缝线的凹陷立体感。
6. **胸口锚点用解剖比例反推**：瞳距 ≈ 0.32 头高、眼睛在头高 0.5 处、胸线在 1.6 头高，所以「眼到胸」≈ 3.4 倍瞳距。再用人体框做一次范围兜底，防止脸的尺度估歪把蛛徽甩到脸上。
7. **切换瞬间**，从手指捏合的屏幕坐标发射一圈正弦涟漪、随距离指数衰减，叠加进位移做爆发式冲击波转场，并沿波前扫过一层蛛网。
8. **传送窗**：双手各摆一个 L，取四个指尖的包围盒当窗口；窗内换肤 + 背景赛博夜雨化，窗框做 RGB 三通道错位的色散 + 呼吸霓虹光。双手合拢即收窗。

**可调参数（实时滑块）**：战衣强度、蛛网密度、布料网格、面罩眼睛、边缘柔度、边光强度、赛博背景、反光/湿度。支持三套皮肤（经典红蓝 / 格温白 / 共生体黑）、前后摄像头切换、镜像、截图、录制 webm。

**关键词**：MediaPipe / WebGL2 / GLSL / SDF / selfie segmentation / hand gesture / screen-space material / row-wise torso axis / procedural suit

**最终**：对镜头一捏手，战衣从手指炸开、顺着身体铺满，抬手、转身、走近走远都跟得住，边缘干净、蛛网贴身、可实时调参。

## 调参建议

- **人小 / 离得远**：布料网格调低（60~90），否则六边形密成噪点
- **边缘发虚**：边缘柔度降到 1.0 左右
- **想更像电影**：反光/湿度拉到 0.9，赛博背景 0.7
- **纯人像不要背景特效**：赛博背景拉到 0

## 为什么不用 MediaPipe legacy solutions

第一版用的是 `@mediapipe/hands` + `selfie_segmentation` + `face_mesh` 这套 legacy script，结果在真机上**永久卡在「正在加载模型…」**。两个独立的坑叠在一起：

1. **三个 legacy solution 的 script 共享全局 Emscripten `Module`**。光是同时加载就互相污染，报 `Aborted(Module.arguments has been replaced with plain arguments_)`，而且 `locateFile` 会串到别的包目录去请求资产 —— `selfie_segmentation/` 下面找 `hands_solution_packed_assets.data`，必然 404。串行 `await initialize()` 也救不了，因为污染发生在 script 加载阶段。
2. **架构错了**：「进入」不该依赖模型加载完成。第一版在 go handler 里 `await` 了模型初始化，CDN 一慢就死锁在按钮上，用户只能看着一个转不动的按钮。

修法：换成 `@mediapipe/tasks-vision`（ESM，三个 task 共享同一份 wasm fileset，官方设计支持共存），并且把 wasm + 三个模型全部下到 `assets/` 本地。启动顺序改成 **摄像头就绪 → 立刻进画面 → 模型后台串行加载 → 就位后功能自动生效**，任何一个模型挂掉都只是对应功能不可用，面板按钮和滑块照常能玩。

顺带修的：`video` 元素原来是 `2px + opacity:.01 + 移出视口`，某些 WebView / 内置浏览器会判定它不可见而**不解码**，于是 `videoWidth` 永远是 0，无限 `await` 静默卡死。现在留在视口内、有真实尺寸、靠 z-index 被画布盖住，并且等 metadata 带 6 秒超时 + track settings 兜底。

`smoke_test.py` 的 H 段专门守这个 bug：源码级检查 `initMP` 必须在进入渲染之后且不被 await，行为上断言点击 2 秒内必须已进画面。

## 黑屏排查：三层根因，全部零报错

「进得去但整屏全黑」出现过三次，根因完全不同，而且**三次都不抛任何异常**。所以按 `I` 打开的诊断面板是唯一可靠信息源 —— 它逐层报告 摄像头流 → 解码 → 纹理上传 → 抠像 → 手势，第一个断掉的环节就是根因。

### 一、`texImage2D(video)` 失败被空 catch 吞掉

`upload()` 原来写成 `try{ ... }catch(e){}`。而 `texImage2D` 传 video 元素在部分 WebView 里**不抛异常，只设 GL error**，于是纹理是全黑而代码一路「成功」。

修法：改用显式 `gl.getError()` 判定，并加**三级相机路径** —— 路径 A 直传 video，路径 B 走 `video → 2D canvas → 上传 canvas`。`probeCamTexture()` 上传后用 framebuffer `readPixels` 回读中心像素，一旦「video 解码正常但纹理全黑」就自动切到 B。面板上有「相机路径」按钮可以手动切。

### 二、探测调度用帧号，低帧率下永远不触发

自动切路径 B 的探测原来是 `frameNo % 22 === 0`。软件渲染 / 低端 GPU 上一帧可能 0.5s，22 帧要十几秒才凑齐一轮，于是「自动降级」实际上从不生效。**帧号不是计时器** —— 改成按时间 `now - lastProbeT > 0.35`。

### 三、`track.muted === true`：摄像头开着但一帧不吐

最隐蔽的一个，在 MiniMax Code 内置浏览器（Electron WebView）里 100% 复现：

- `getUserMedia` 成功，`stream` 有效
- `track.readyState === 'live'`、`track.enabled === true`
- **macOS 摄像头指示灯是亮的**
- 但 `track.muted === true` → `video.readyState` 停在 `0/4`、`videoWidth` 恒为 0、整屏全黑

原来的代码在 `waitMeta(6000)` 超时后走 `track.getSettings()` 兜底拿分辨率继续启动 —— 那只是**把黑屏伪装成「已启动」**。而且诊断的结论句把它归到「被别的 App 抢走了」，完全指错方向（轨道明明是 live）。

关键区分：**`muted` 和 `ended` 是两回事**。`ended` 不可恢复；`muted` 由 source 决定、会以 `unmute` 事件解除，是可恢复状态。所以修法是挂 `mute` / `unmute` 监听，`unmute` 后重新等 metadata、重置探测状态、恢复渲染；同时在轨道 muted 时明确报出「请改用 Chrome 打开 localhost:8080」而不是含糊的失败。

内置 WebView 的 muted 限制页面侧无法绕过，**这个 demo 必须用 Chrome / Edge 打开**。

### 顺带清掉的空 catch

`runDetect()` 里三个模型各有一个 `catch(e){/* 单帧失败不致命 */}`。单帧失败确实不致命，但**静默吞掉会让「模型就绪却永远不出结果」在面板上毫无痕迹**。现在异常记进 `DIAG.detErr` / `detErrN`（最后一条 + 累计次数），面板只在真抛过时显示该行。`analyzeGrid()` 外面那个 `try/catch` 直接删了 —— 里面全是纯算术，出错就是真 bug，必须暴露；顺手发现它下面 `const bb = S.bbox` 是死变量。

对应测试：`smoke_test.py` 的 I 段（摄像头→纹理链路 + 诊断面板）、J 段（用 `Object.defineProperty` 真实注入 muted 轨道，断言 DIAG 记录 + 结论句指向 muted + 给出 Chrome 出路）、K 段（源码级禁止空 catch）。四刀故意破坏对照：摘 unmute 监听 → 1 红；verdict 退回旧文案 → 2 红；手势 catch 退回空 catch → 2 红；探测退回按帧号 → 1 红。

## 传送窗交互：移植 sophiamyang/finger-frame-effect

参照 [finger-frame-effect](https://github.com/sophiamyang/finger-frame-effect)（同系列还有 -ai / -lucy 两个变体，仓库已 clone 到 `ref/ffe-live/`、`ref/ffe/`）把传送窗从「轴对齐矩形」升级成完整的取景窗管线：

1. **任意四边形**：四角直接用双手拇指/食指指尖（解剖学顺序 A食指→B食指→B拇指→A拇指，A=腕x小的手），窗口跟着手的姿态旋转/透视。shader 里用到边最近距离替代 `sdBox`；内部判定用**射线法（even-odd）**——「所有边同侧」只对凸四边形成立，双手一转，角点会连成自交的「蝴蝶结」，同侧判定直接把窗内判成空（用户实测复现）。even-odd 把蝴蝶结填成两个三角形，与原版 canvas `clip()` 的行为一致。
2. **开窗/维持双阈值迟滞**：开窗要求张开 > 0.75×手长且三指收起；维持只要求 > 0.20 —— 手指微动不闪断。面积闸同理（0.005 → 0.0005）。
3. **Teleport rejection**：整体位移 > 0.3 屏宽的孤立帧当误检丢弃，连续 2 帧才认（手势模型偶发把别的东西认成手）。
4. **速度自适应平滑**：α = clamp(moved/0.05, 0.35, 0.85) —— 快甩手跟紧、慢移动稳住。
5. **掉帧按时间保持**：检测断 0.9 秒内窗口原地保持（按时间不按帧数），之后才由 portal 渐隐收拢。
6. **Marching-ants 虚线 + 呼吸角点**：沿四边形周长的弧长参数做行进虚线，四角白点 + 向外扩散的光晕环 —— 原 demo 的标志性视觉，全部在 fragment shader 里完成。

对应测试：`smoke_test.py` 的 L 段 —— 像素级断言 debug 绿线出现在斜 quad 的斜边上而不是外接 bbox 的水平边上（细线用逐像素峰值 `max(g-max(r,b))` 检测，均值会被背景稀释）；蝴蝶结姿态注入交换 2/3 角的自交 quad，采样上三角质心断言红占优（`__PORTAL_TEST__` 会强制 suit=0，否则全身开着窗内外无对比、断言永真）；行为级用伪造 landmarks 走真实 `onGesture` 管线，逐条验证迟滞 / teleport rejection / 掉帧保持。五刀破坏对照：shader 塌回 bbox → 2 红；摘迟滞 → 1 红；摘 teleport rejection → 2 红；掉帧立刻收窗 → 1 红；even-odd 换回同侧判定 → bowtie 断言 1 红。

## 背景：城市上空 view + 战衣质感雕刻

参照 Homecoming 海报（高机位俯瞰纽约天际线）：

- **背景**从赛博夜雨换成程序化城市白天：渐变蓝天（顶部深蓝→地平线雾白）+ fbm 絮云 + 右上阳光 + 三层带视差的楼群剪影（远层淡蓝、近层深色亮窗，空气透视）。地平线压在 0.86 —— 近景人像场景里天际线只该是画面底部一条远景装饰带，第一版 0.52 把人下半身糊进楼群，实测明显不对。楼群坐标约定：p.y=0 是地平线，楼向上长、向下填满画面底（不设下边界，否则楼群悬空成一条噪声带）。窗格行高 ~1.5% 画高，再小 step() 会闪成静电噪声。
- **战衣质感**：六边形面板中心鼓起（panelBulge 进法线 N，主光照/高光/边光全部真实响应凹凸）+ 高频纤维噪声 + 缝线「暗沟 + 亮边」双层结构（seamCore/seamRim，有厚度感）。经典红蓝的边光从霓虹粉改成阳光暖白 —— 白天城市光环境下霓虹粉出戏。
- **坑**：GLSL ES 保留字 `half` 不能当变量名；`h11` 只吃 float，vec2 要用 `h21`。

对应测试：M 段 —— 源码级（cityscape/panelBulge/seamRim、rain 死代码已删）+ 像素级（天空两点亮蓝 b>r+35、楼群带四点 b<145，阈值来自实测留 15+ 余量）。破坏对照：`bgAmt=0` → 天空断言精确报红。bowtie 断言同步升级为「窗内 vs 窗外同点色差 Δ>60 多数决」—— 上三角正盖着胸口蛛徽+银网+高光，「红占优」语义会被单点高光冲掉（实测 r-b 从 +42 掉到 +2），「被窗显著改变」才是「窗内出效果」的本义。

## 蛛徽只画在胸口：脸部特写要关掉它

用户实测：脸怼到镜头前时，胸口蛛徽爬到鼻子上。

根因不是位置算错，是**画面里根本没有胸口**。`cy = 眼睛 + 3.4×瞳距` 算出的胸口落在画面外，随后的 `clamp(cy, 框内)` 把它硬拉回来 —— 而那个"人体框"就是一张脸。也就是说 clamp 这个兜底逻辑在特写场景下反而制造了 bug。

修法：`uChest` 升为 vec3，z 分量是**胸口可见度** = `1 - smoothstep(0.20, 0.30, 瞳距/框高)`。正常半身像这个比值约 0.10~0.16（可见度 1），脸占满帧时飙到 0.3+（可见度 0，蛛徽淡出）。蛛网网面保留（战衣全身都有网），但中心那圈径向汇聚点也按可见度淡掉 —— 否则脸中央会出现一朵刺眼的"太阳花"。

对应测试：N 段 —— `__CLOSEUP_TEST__(closeup)` 注入两套 mask（半身像 / 大头照）走真实 `computeBBoxFromMask`，断言 chestVis 分别收敛到 1 和 0；像素证据用 `__FORCE_CHEST_VIS__(1)` 做「闸门开 vs 关」的 diff 对照（Δ>40 多数决），不猜蛛徽落点、不断言具体颜色。两刀破坏对照：摘 shader 侧闸门 → 2 红；chestVis 恒为 1 → 2 红。

**这里踩了一个假绿**：第一版像素断言是「特写时脸中央必须是战衣红」，采样点 y=0.40。摘掉闸门跑破坏对照时它**没有报红** —— 因为那点根本不在人身上（是背景，无论有没有蛛徽都是黑的）。断言等于永真。改成 diff 对照后才有牙齿。教训：断言「某处该是什么颜色」之前，先确认那个采样点真的落在被测物上。

## 蜘蛛格温（按键 2）：兜帽 + 洋红蛛网 + 粉紫夜城

按 Into the Spider-Verse 的格温重做（参考图：白连帽卫衣 + 洋红蛛网袖 + 黑胸腹 + 白蛛徽 + 青绿芭蕾鞋 + 大月亮夜城）。切到这套皮肤时背景自动转夜景。

**兜帽的硬限制**：只有人体轮廓 mask，帽子**画不到轮廓外**（超出部分被 alpha 切掉）。第一版按参考图外扩 2.05×2.30 span 画，全被裁掉，头上什么都没多出来。改成「沿头部轮廓内侧的一圈白色宽边 + 帽口洋红内衬」——mask 内的头顶/两颊铺白布，中间露出面罩，这是这套输入能做到的最接近读法。

**帽口尺寸是关键**：帽体 = mask 内、帽口外那一圈。帽口 0.86×1.16 时帽体只占头部窗口 3%（等于没画，用户只看到一圈粉边）；收到 0.74×1.00 后是 18.7%，才读得出"帽子罩着头"。

**白粉比翻正**（归因实验的教训）：第一版整条手臂读成"粉袖子"（粉 28% / 白 11%），和参考图的"白衣 + 细网线"完全反了。我先猜边光、再猜网线宽度，**两次都错**。纯色替换归因（把各粉色来源逐个染绿/关闭）才定位到：菱形网是唯一主凶（关掉后手臂粉 28%→1%、白 11%→38%），边光贡献 0%，帽口内衬约 11%。而且这层网**覆盖率本身就有 30%**，收线宽治不了 —— 最终靠降混合 alpha 到 0.42 + 给格温单独加 0.16 环境项提亮白布，才把比例翻成 粉 8% / 白 33%。

对应测试：O 段 —— 源码级（uHood/帽口 taper/洋红 web/白蛛徽/青绿鞋/夜景 night+月亮）+ 像素级（夜空变暗且偏洋红、月亮亮于夜空、格温手臂亮于经典款）+ **两条守美术目标的比例断言**（手臂白 ≥ 2.4×粉；兜帽几何覆盖 ≥ 15%）。三刀破坏对照全部精确报红。

**这轮踩了三个假绿**，都值得记：
1. 旧断言写「手臂粉像素占比 > 70%」—— 它正好**锁死了错的美术目标**（粉袖子那版）。改成"开/关网线粉像素显著变化"才是对的语义。
2. 「手臂白 > 粉 × 1.3」阈值卡在两端之间（正常 3.6 / 粉袖子 1.5），破坏对照不报红。必须**用实测两端数据定阈值**，取 2.4。
3. 兜帽断言最初去数画面白像素 —— 帽口一放大，露出的面罩本身也是浅色被算成帽布（0.301 vs 0.268，读不出差异）。改用 `uDebug==2` 的**几何探针**（帽体覆盖直接输出成纯绿）才测得准；阈值也从 0.10 修到 0.15（回退版实测 0.116）。

## 已知边界

- **必须用 Chrome / Edge。** 内置浏览器（Electron WebView）给出的摄像头轨道是 `muted` 的，页面侧无解，见上文根因三。
- 只有一个 Selfie Segmentation 的人体 mask，没有 3D 姿态骨架，所以战衣是「屏幕空间贴合」而不是真 3D 蒙皮 —— 快速大幅度动作时布料不会有布料物理。
- 分区依赖逐行躯干轴的启发式：手臂紧贴身体时会被算进躯干（视觉上问题不大），但双腿大幅分开站立时腿部分区可能偏移。
- 三个模型同时跑，M 系列 Mac 大概 20~30fps。嫌卡可以把面部模型的隔帧数从 2 调大（代码里 `faceTick % 2`），代价是面罩跟头会略滞后。
- `assets/` 约 36MB（wasm 12MB + 手部模型 7.5MB + 面部模型 4.3MB + 抠像模型 244KB）。首次打开要从本地读这些，稍等几秒；之后浏览器会缓存。

## 文件

- `index.html` — 全部实现，单文件无构建（ESM module script）
- `assets/` — tasks-vision 的 wasm + 三个模型，本地化，无 CDN 依赖
- `smoke_test.py` — 冒烟测试（shader 编译、渲染管线、像素证据、手臂/腿部分区、溢色回归），每条断言都配了故意破坏对照
- `shot_skins.py` — 三套皮肤的验收截图脚本
- `start.sh` — 本地起服务

> 注：文中提到的 `ref/`（电影剧照、参考 demo 视频、finger-frame-effect 仓库 clone）和 `shots/`（截图产物）**不在仓库里** —— 前者是第三方版权素材，后者是可再生成的产物。`shot_skins.py` 会自己创建 `shots/`。
